# Context Vault & MCP

Context Vault is OpenSelf's local, durable memory layer. It is designed to give an AI enough
relevant context for a task without handing the AI an unfiltered transcript of the user's life.

## Design principles

1. **Memory is data, not a hidden prompt.** It has a schema, an ID, timestamps, and lifecycle.
2. **Provenance travels with content.** A retrieved claim should be traceable to its source.
3. **Current truth beats semantic similarity.** Validity windows prevent stale memories from being
   treated as current.
4. **Least context by default.** Scope, sensitivity, result count, and character budget constrain
   every retrieval.
5. **Forgetting is a first-class operation.** Soft-deleted memories immediately disappear from FTS
   and context building while retaining a local audit record.
6. **Storage is model-independent.** No LLM or embedding API is needed to store and search memory.

## Schema

| Field | Meaning |
|---|---|
| `id` | UUID generated by OpenSelf |
| `type` | fact, preference, decision, commitment, relationship, event, or note |
| `content` | Canonical memory text |
| `summary` | Optional compact label |
| `source` | Source kind, locator, and title |
| `scope` | Hierarchical boundary such as `project/acme/billing` |
| `sensitivity` | public, personal, private, or restricted |
| `confidence` | Confidence from 0 to 1; not a claim of objective truth |
| `validFrom` / `validTo` | Interval in which a fact or preference should be treated as current |
| `occurredAt` | When an event happened |
| `tags` | Normalized retrieval and organization labels |
| `status` | active or forgotten |
| lifecycle timestamps | created, updated, and forgotten timestamps |

Dates use ISO 8601 with an explicit offset. A memory whose validity window does not contain the
requested `asOf` time is excluded from search.

## Scope semantics

Scopes are hierarchical. Asking for `project/acme` can return `project/acme/billing`, but it cannot
return `project/other` or `personal` memories. Callers should always request the narrowest useful
scope.

Scope is currently a retrieval boundary, not an operating-system access control list. Any local
process with direct access to `context.db` can read the database. Filesystem protection and a future
encrypted vault remain separate concerns.

## Sensitivity semantics

Sensitivity is ordered:

```text
public < personal < private < restricted
```

Search only returns memories at or below `maxSensitivity`. MCP search/context default to `private`,
which means `restricted` data requires an explicit caller decision. Applications serving multiple
users must add authentication and authorization outside this local stdio server.

## Retrieval

The first implementation uses SQLite FTS5 with Unicode tokenization, followed by deterministic
filters for status, scope, type, sensitivity, and validity time. Results are ranked by BM25,
confidence, and recency.

This deliberately avoids an embedding API in the trusted storage path. A future hybrid retriever
may add local vectors and reciprocal-rank fusion, but SQLite remains the canonical store and all
security filters apply after candidate generation.

## MCP tools

### `openself_remember`

Creates one memory. Agents should use a precise `sourceLocator`, avoid storing secrets unless the
user explicitly requests it, and distinguish an observed fact from an inferred preference using
`type` and `confidence`.

### `openself_search_memory`

Returns structured memory records. Use it when the application needs to inspect or cite individual
memories.

### `openself_get_context`

Returns a compact formatted context block plus the contributing records. Use it before a bounded
task such as preparing a meeting brief or drafting a status update.

### `openself_forget`

Soft-deletes a memory by UUID. It becomes unavailable to normal reads and is removed from FTS.

## Client configuration

Install globally or let the client invoke the npm package:

```json
{
  "mcpServers": {
    "openself": {
      "command": "npx",
      "args": ["-y", "openself", "mcp"],
      "env": {
        "DATA_DIR": "/absolute/path/to/openself-data"
      }
    }
  }
}
```

Use a dedicated data directory for real personal context. Do not commit `context.db`, its WAL files,
or imported personal data to Git.

## Current limitations

- No encrypted-at-rest vault or OS keychain integration yet.
- No semantic/vector retrieval yet; synonyms may require tags or explicit wording.
- No automatic conflict resolution between memories.
- No multi-user ACL or authenticated HTTP transport.
- No connector ingestion pipeline into the new schema yet.
- Forgotten rows are recoverable locally and are not cryptographically erased.
